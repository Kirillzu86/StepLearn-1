# StepLearn — Backend (Django REST Framework)

Полноценный бэкенд платформы онлайн-обучения StepLearn на Python 3, Django и Django REST Framework (DRF), совместимый с React/Vite фронтендом и Nginx/Docker/Coolify инфраструктурой.

---

## Что где находится (Архитектура проекта)

```text
backend/
├── Dockerfile                  # Multi-stage сборка Docker-образа для бэкенда
├── entrypoint.sh               # Скрипт ожидания PostgreSQL, авто-миграций и seed_demo
├── manage.py                   # Главная точка входа для команд управления Django
├── requirements.txt            # Зависимости Python (Django, DRF, psycopg, cors-headers, gunicorn и др.)
├── .env.example                # Пример переменных окружения
│
├── steplearn/                  # Главный конфигурационный пакет Django
│   ├── settings.py             # Настройки проекта (БД, CORS, ALLOWED_HOSTS, DRF, custom exception handler)
│   ├── urls.py                 # Корневые маршруты (включает api.urls как с префиксом /api/, так и без)
│   ├── asgi.py                 # ASGI-интерфейс для асинхронных серверов
│   └── wsgi.py                 # WSGI-интерфейс для Gunicorn / production
│
└── api/                        # Основное приложение платформы
    ├── models.py               # Модели БД: User, Course, Question, Answer, Enrollment (с прогрессом)
    ├── serializers.py          # DRF-сериализаторы (валидация, хеширование, вложенные вопросы/ответы)
    ├── views.py                # Контроллеры API (аутентификация, каталог, прогресс, профиль)
    ├── urls.py                 # Маршрутизация эндпоинтов API
    ├── exceptions.py           # Кастомный обработчик ошибок (гарантирует наличие поля detail для фронтенда)
    ├── migrations/             # Миграции схемы базы данных
    │   └── 0001_initial.py     # Начальная миграция всех моделей
    ├── management/
    │   └── commands/
    │       └── seed_demo.py    # Команда наполнения демо-данными (курсы, вопросы, студент, админ)
    └── tests/
        └── test_api.py         # Набор автотестов для всех сценариев API
```

## Модели базы данных (`api/models.py`)

1. **`User` (кастомная модель на базе `AbstractUser`)**:
   - `username`, `email` (уникальный), `password` (хешируется PBKDF2/SHA256).
   - `avatar_url` (ссылка или base64 аватарка до 5MB).
   - `role`: `student`, `teacher` или `admin`.
   - Свойство `.name` — возвращает имя или логин (для обратной совместимости с React фронтендом).
2. **`StudentProfile` и `TeacherProfile`**:
   - Отдельная запись One-to-One для аккаунта соответствующей роли.
   - Профиль создаётся автоматически при создании аккаунта; миграция заполняет
     профили для уже существующих учеников и преподавателей.
3. **`Course`**:
   - `title`, `description`, `price` (0 = бесплатно, >0 = платно).
   - `rating` (по умолчанию 4.5+).
   - `author` (связь с `User`, создавшим курс).
   - `students` (`ManyToMany` через таблицу `Enrollment`).
   - `created_at` (дата создания).
4. **`Question`**:
   - `course` (`ForeignKey` на курс).
   - `text` (текст вопроса теста).
5. **`Answer`**:
   - `question` (`ForeignKey` на вопрос).
   - `text` (текст ответа).
   - `is_correct` (булевый флаг правильности ответа).
6. **`Enrollment` (запись на курс и отслеживание прогресса)**:
   - `user`, `course` (уникальная пара `user + course`).
   - `current_index` (номер текущего вопроса).
   - `progress_percentage` (процент прохождения 0-100%).
   - `completed_lessons` (количество пройденных уроков/вопросов).
   - `correct_answers` (количество верных ответов).
   - `created_at`, `updated_at`.

## Доступные маршруты API

Все маршруты доступны **как с префиксом `/api/`, так и без него** (например, `/auth/login` и `/api/auth/login`), что предотвращает ошибки при проксировании через Nginx и при локальном Vite dev-сервере.

### Аутентификация и пользователи
| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/auth/teacher/register` (или `/api/auth/teacher/register`) | Регистрация преподавателя |
| `POST` | `/auth/login` (или `/api/auth/login`) | Вход по `login` (username или email) и `password` |
| `POST` | `/auth/refresh` (или `/api/auth/refresh`) | Обновление access token по refresh token |
| `POST` | `/auth/logout` (или `/api/auth/logout`) | Отзыв refresh token |
| `POST` | `/auth/change-password` (или `/api/auth/change-password`) | Смена пароля текущего пользователя; для временного пароля обязательна |
| `POST` | `/v1/lessons/{id}/complete` | Завершение урока текущим учеником; требуется JWT, пользователь определяется по токену |
| `/v1/blocks/{id}/exam` | — | Чтение требует JWT; создание/изменение доступно только teacher/admin |
| `GET` | `/v1/exams/{id}` | Получение экзамена текущей сессии; правильные ответы скрыты для ученика |
| `POST` | `/v1/exams/{id}/submit` | Сдача экзамена текущим учеником; требуется JWT, подмена `user_id` запрещена |
| `GET` | `/v1/teacher/dashboard` (или `/api/v1/teacher/dashboard`) | Дашборд; требуется access token преподавателя или администратора |
| `/v1/teacher/students/*` | — | Управление студентами; требуется access token преподавателя или администратора |
| `POST` | `/v1/groups` | Создание группы с `capacity` и списком учеников `{first_name, last_name}`; аккаунты создаются атомарно, возвращаются временные credentials |
| `/v1/groups/*` | — | Просмотр и управление группами; требуется JWT, преподаватель управляет только своими группами |
| `POST /v1/groups/{id}/assign-course` | — | Назначение курса группе создаёт enrollment её учеников |
| `POST /v1/groups/{id}/lessons/{lesson_id}/toggle-access` | — | Открытие или закрытие назначенного группе урока преподавателем |
| `POST /v1/groups/join` | — | Самостоятельное вступление ученика запрещено; в группу учеников добавляет преподаватель |
| `GET` | `/users` (или `/api/users`) | Список пользователей; только преподаватель или администратор |
| `GET` | `/v1/users/{id}` (или `/api/v1/users/{id}`) | Профиль владельца или пользователя с ролью teacher/admin |
| `PUT`/`PATCH` | `/v1/users/{id}` (или `/api/v1/users/{id}`) | Обновление собственного профиля; роль изменять нельзя |

### Курсы и каталог
| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/v1/courses` (или `/api/v1/courses`) | Публичный каталог опубликованных курсов; преподаватель видит собственные курсы (поддерживает поиск `?q=...`) |
| `POST` | `/v1/courses` (или `/api/v1/courses`, `/v1/courses/create`) | Создание курса; требуется JWT teacher/admin, автор берётся из токена |
| `GET` | `/v1/course/{id}` (или `/api/v1/course/{id}`) | Опубликованное описание публично; draft/archive доступны только автору и администратору. Материалы видны автору, администратору или записанному ученику; заблокированный урок возвращается без содержания |
| `PATCH` | `/v1/course/{id}` (или `/api/v1/course/{id}`) | Изменение метаданных и статуса (`draft`, `published`, `archived`); только автор курса или администратор |
| `GET` | `/v1/courses/{id}/blocks` | Просмотр блоков автором/администратором или записанным учеником опубликованного курса |
| `POST` | `/v1/courses/{id}/blocks` | Создание блока только автором курса или администратором |
| `POST` | `/v1/courses/{id}/quiz/submit` | Проверка всех ответов quiz на сервере; записываются фактическое количество верных ответов и завершение курса без уроков |
| `POST` | `/v1/courses/{id}/complete` | Отметить завершённым только назначенный опубликованный текстовый курс без отдельных уроков и quiz; требуется JWT ученика |
| `GET`/`POST` | `/v1/courses/{id}/assignments` | Список доступных заданий курса или создание задания типа `text`, `short_answer`, `quiz`, `multiple_choice`, `file_upload` или `code`; Code Assignment поддерживает Python/JavaScript, шаблон, подсказки и до 100 скрытых тест-кейсов (ввод/ожидаемый вывод доступны только автору/администратору; выполнение не реализовано) |
| `GET`/`PATCH`/`DELETE` | `/v1/assignments/{id}` | Просмотр задания учеником или автором; редактирование и удаление — автором/администратором; удаление запрещено после отправки ученических ответов |
| `GET`/`POST` | `/v1/assignments/{id}/submissions` | Ученик отправляет текст, `source_code` (до 50 000 символов) для задания `code`, `{answers: [{question_id, option_ids}]}` для теста или multipart-файл (PDF/TXT/PNG/JPEG до 10 МБ); quiz автоматически оценивается на сервере, запуск исходного кода не выполняется, файл отдаётся только ученику-владельцу и автору/администратору |
| `GET` | `/v1/submissions/{id}/file` | Скачивание вложения ответа через приватный endpoint; файлы хранятся вне публичной раздачи |
| `PATCH` | `/v1/submissions/{id}/grade` | Ручная проверка ответа автором курса или администратором с оценкой в пределах баллов задания и отзывом |

### Запись на курс и прогресс обучения
| Метод | Путь | Описание |
|---|---|---|
| `POST` | `/v1/enroll` (или `/api/v1/enroll`) | Назначение опубликованного курса конкретному ученику; преподаватель назначает только свой курс, администратор — любой; требуется JWT teacher/admin |
| `GET` | `/v1/users/{id}/courses` (или `/api/v1/users/{id}/courses`) | Список курсов владельца профиля; teacher/admin могут просматривать пользователей |
| `POST` | `/v1/users/{id}/courses/{course_id}/progress` | Ручная коррекция прогресса только автором курса или администратором; ученический прогресс фиксируют завершение урока, quiz и текстового курса |
| `GET` | `/v1/users/{id}/courses/{course_id}/progress` | Получение прогресса курса и `learning_progress` по разделам, урокам и опубликованным заданиям владельца профиля; в разрезе задание считается завершённым после последней оценённой отправки. `learning_progress.progress_percentage` — агрегат по урокам и заданиям; legacy `progress_percentage` остаётся полем Enrollment; требуется JWT |

## Формат ошибок

Все ошибки API (400, 404, 500) автоматически форматируются с гарантированным полем **`detail`** (через `api/exceptions.py`), что позволяет фронтенду корректно выводить понятный текст ошибки пользователю:
```json
{
  "detail": "Неверный логин или пароль"
}
```

## Настройки окружения и база данных

Backend использует кастомную модель `api.User`, роли `student`, `teacher`,
`admin`, а также отдельные профили ученика и преподавателя. Профили создаются
автоматически при создании пользователя; миграция переносит существующие
аккаунты в соответствующие таблицы.

Для локального запуска Django загружает `backend/.env`. Скопируйте
`backend/.env.example` в `backend/.env` и укажите реквизиты существующей
PostgreSQL-базы. Пароль PostgreSQL и Django secret key не имеют встроенных
production-значений: при `DJANGO_DEBUG=0` приложение останавливается с явной
ошибкой, если секреты или пароль БД не заданы. Для тестов допустимо явно
выбрать SQLite через `USE_SQLITE=1`.

Для Docker Compose скопируйте корневой `.env.example` в `.env` и замените все
значения `replace-with-...` случайными секретами и своими настройками домена.
Compose теперь не запускает базу и backend с общими паролями, wildcard-hosts
или открытым CORS по умолчанию.

## Локальный запуск (без Docker)

1. Активируйте виртуальное окружение:
   ```bash
   # Windows PowerShell:
   .\.venv\Scripts\Activate.ps1
   # или Linux/macOS:
   source .venv/bin/activate
   ```
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
3. Создайте `.env` (или скопируйте `.env.example`):
   ```bash
   copy .env.example .env
   ```
   Укажите в `POSTGRES_PASSWORD` пароль существующего локального PostgreSQL
   пользователя. Django автоматически загружает `backend/.env`; переменные,
   переданные процессу или Docker, имеют приоритет над значениями файла.
   Для разработки без PostgreSQL установите `USE_SQLITE=1`.
4. Примените миграции:
   ```bash
   python manage.py migrate
   ```
5. Заполните базу демо-данными:
   ```bash
   python manage.py seed_demo
   ```
   *Создаются тестовые аккаунты:*
   - Студент: `student` / `secret123`
   - Администратор: `admin` / `admin123`
6. Запустите тесты:
   ```powershell
   $env:USE_SQLITE = "1"
   $env:DJANGO_DEBUG = "1"
   python manage.py test api --noinput
   ```
7. Запустите сервер разработки:
   ```bash
   python manage.py runserver 0.0.0.0:8000
   ```

## Запуск через Docker Compose

В корне проекта:
```bash
docker compose up --build -d
```
Бэкенд автоматически:
1. Дождется запуска PostgreSQL.
2. Применит все миграции.
3. Заполнит базу демо-данными `seed_demo`.
4. Запустит сервер на порту `8000`.
